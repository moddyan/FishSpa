# Fish Spa - 原型设计简报

日期：2026-06-11

记录约定：未标记内容表示已经在讨论中明确提出或达成共识的方向。`<AI>...</AI>` 表示 Codex 补充的设计判断、表述或建议，后续都可以调整。

## 当前前提

这个想法来自自然界里的共生关系：鲸鱼等大型海洋生物需要小鱼帮它们清理口腔中的残渣。

项目方向是把这个意象发展成一个真正可玩的游戏。经过初步市场调研，目前几乎没有围绕这个具体题材做出成熟可玩性的游戏，所以这个方向存在一定题材空位。

最终形态可能很适合多人联机合作，因为这个题材天然会产生混乱、分工、误操作、互相呼喊和喜剧感。不过第一阶段应该先从单人验证原型开始。

最终体验倾向 3D 第三人称，而不是 2D 俯视。2D 可以验证任务节奏，但很难验证这个题材最独特的体验：玩家作为一条小鱼，真的钻进巨大生物的嘴里工作。

当前项目由一名 Unity 工程师和 AI 协作推进。原型引擎选择 Unity。

## 一句话方向

<AI>一款 3D 第三人称合作清洁动作游戏：玩家扮演小鱼，进入巨型海洋生物的口腔，清理残渣、寄生物和污染物，躲避活体空间的反应，并和这些巨大的客户建立信任。</AI>

<AI>第一阶段原型先收窄为：玩家控制一条小鱼进入鲸鱼嘴，在嘴巴闭合前清理足够多的污渍，躲过舌头和水流等危险，然后成功逃出。</AI>

## 核心幻想

玩家很小。

客户很大。

关卡是活的。

清洁这件事既有用、亲密、危险，又带一点荒诞喜感。

<AI>这个项目最强的差异化不是“海洋”或“环保”，而是“在一个会反应的活体空间里工作”。</AI>

## 设计支柱

### 小小工作者，巨大身体

玩家和巨型生物之间的尺度反差要非常明确。牙齿、舌头、牙龈、上颚、喉咙、唾液、水流都应该让玩家感到自己很小。

<AI>鲸鱼嘴不能只是一个带嘴巴装饰的房间，而应该像一台玩家临时进入的、柔软潮湿的活体机器。</AI>

### 活体关卡

鲸鱼嘴不是静态地形。

<AI>它可以呼吸、抽动、咳嗽、产生水流、用舌头横扫、随着倒计时逐渐闭合，并根据玩家的清洁或失误产生反应。</AI>

### 有用的混乱

游戏应该制造好笑的压力，但不能变得看不懂。

<AI>理想的第一次试玩感受是：“我知道自己要干什么，但整个嘴都在动，我差一点才逃出来。”</AI>

### 未来合作，先做单人

长期方向可以支持多人合作。

第一版原型保持单人，用来证明在没有其他玩家制造气氛的情况下，核心动作循环本身也成立。

<AI>多人应该是放大核心乐趣，而不是掩盖核心玩法不好玩。</AI>

## 原型目标

验证一个问题：

<AI>第三人称控制一条小鱼，在会动的鲸鱼嘴里清理污渍，这件事是否紧张、好笑、并且让人想再来一局？</AI>

第一版可玩切片要足够小，方便快速搭建和调手感。

## 第一版可玩切片

### 场景

一个灰盒鲸鱼嘴。

嘴里包含：

- 上颚和下颚
- 牙齿或类似牙齿的阻挡物
- 舌头
- 可以附着污渍的牙龈或口腔壁面
- 喉咙方向或出口方向
- 清晰的入口和逃生点

<AI>第一版只需要简单几何体。用 ProBuilder 式的 blockout 就够，验证阶段不追求美术完成度。</AI>

### 玩家

玩家控制一条第三人称小鱼。

第一版预期操作：

- 游动/移动
- 上浮/下潜，或者等价的 3D 位移方式
- 朝移动方向或镜头方向转向
- 短距离冲刺
- 清理/交互

<AI>小鱼可以先用胶囊体、简单模型或占位模型。优先级是移动手感、镜头可读性、碰撞和清理反馈。</AI>

### 目标

第一关放置少量可清理目标。

初始目标类型候选：

- 食物残渣：基础清理目标
- 寄生物：更活跃或更危险的目标
- 塑料垃圾：更重的清理目标，可能需要拖到回收点

<AI>绝对最小版本可以先只做食物残渣。等移动和基础清理稳定后，再加入寄生物和塑料垃圾。</AI>

### 危险

初始危险候选：

- 舌头横扫
- 水流冲刷
- 嘴巴闭合倒计时或闭合阶段

<AI>第一个危险建议先做舌头横扫，因为它可读、物理感强、好笑，并且和“嘴里工作”的幻想直接相关。</AI>

### 单局流程

<AI>原型单局可以先按约 90 秒设计。</AI>

基础循环：

1. 进入鲸鱼嘴。
2. 寻找污渍目标。
3. 一边清理，一边躲避口腔反应。
4. 判断是否冒险多清一点，还是立刻撤离。
5. 成功逃出，或在嘴巴闭合时失败。
6. 显示简单结算。

### 结算

可能的结算指标：

- 清洁度
- 鲸鱼舒适度
- 剩余时间
- 小鱼安全
- 评级

<AI>第一版结算只需要服务于“再来一局”的动机，不需要做长期成长。</AI>

## 第一阶段不做什么

第一阶段不做在线联机。

第一阶段不做完整经营层。

第一阶段不投入最终鲸鱼美术、小鱼动画、UI 精修、经济系统、剧情或大量巨兽种类。

<AI>这些方向后续都可能重要，但当前最大的风险是：3D 活体口腔清洁这个核心动作体验是否成立。</AI>

## 后续方向

### 多人合作

多人合作仍然是长期强方向。

可能的职业分工：

- 清洁鱼：快速清除残渣
- 搬运鱼：移动较重垃圾
- 安抚鱼：降低鲸鱼紧张或疼痛
- 探照鱼：发现污渍或安全路线

<AI>后续建议先做本地合作，再做在线联机。如果本地合作都不够好笑、不够清晰，在线不会解决问题。</AI>

### 单人小队桥接

在真正做多人前，可以用单人小队系统验证分工。

<AI>玩家可以切换不同鱼，或对队友下简单指令。这样能在不做网络的情况下提前验证合作设计。</AI>

### 鱼疗站经营层

游戏后续可以长成一家海底鱼疗站。

可能循环：

- 接待巨型生物客户
- 进入口腔进行动作清洁关卡
- 获得信任和资源
- 升级鱼疗站或小鱼团队
- 解锁更深海域和更奇怪的客户

<AI>经营层应该等动作原型证明手感成立后再展开。</AI>

### 生态主题

清洁幻想可以自然扩展到海洋污染。

塑料、鱼钩、石油、微塑料、受损生态都可以成为游戏对象和叙事压力。

<AI>环保主题应该优先通过玩家正在做的动作表达，而不是靠说教文本表达。</AI>

## 技术起点

引擎：Unity。

当前 Unity 项目：`FishSpaClient`。

当前 Unity 版本：`6000.4.6f1`。

当前已安装或可用的相关包包括：

- URP
- Input System
- Cinemachine
- ProBuilder MCP support
- Unity MCP package
- Multiplayer Center

<AI>第一版技术结构建议：把原型脚本隔离在独立 prototype 目录，不急着做最终架构。先使用轻量 MonoBehaviour 和场景引用，等核心循环稳定后再整理结构。</AI>

## 开放问题

小鱼移动应该有多自由：完整六自由度游动、主要沿镜头平面移动，还是介于两者之间的混合方案？

镜头应该贴在鱼后方、略高于鱼，还是为了可读性拉得更远？

清理交互应该是长按、贴近摩擦、咬除，还是像工具一样的短距离射线/水流？

口腔质感应该有多“真实”：可爱风格、湿润触感、轻微恶心，还是介于中间？

第一版里鲸鱼对失误的反应应该有多强？

我们希望第一个试玩者说出的“这个有意思”的瞬间是什么？
